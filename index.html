先保留旧配置，再做一次更新

如果旧配置仍能使用，先记录当前配置名称、客户端和内核版本、最后一次成功更新的时间。软件支持备份时，将备份留在自己的可信设备中；它可能包含节点密码，不上传公开网盘或仓库。不要删除唯一可用副本，也不要用新下载内容直接覆盖手工维护的规则。

确认正在更新的是自己账户提供的订阅地址，不是网站首页、套餐页或带登录状态的后台页面。到实际提供方账户内核对对应客户端的订阅类型；同一服务可能有多种格式，不能仅凭地址后缀猜格式。

随后只更新一次，记下错误出现于“请求地址”“接收响应”“解析内容”还是“应用配置”。有状态码就保留状态码，只有超时就记录等待时长。不要在截图中展示完整 URL、二维码或含令牌的查询参数。

请求失败：根据错误选择下一步

401、403：先核对地址和账户状态

HTTP 401 表示请求缺少有效认证凭据；403 表示服务端理解请求但拒绝处理。它们是线索，并不能单独证明“套餐到期”或“节点故障”。查看实际提供方账户中的服务有效期、订阅是否被撤销，以及你是否复制了完整地址。不要把网页登录密码填进陌生客户端字段尝试修复。

若刚重置订阅，旧地址可能已经失效。复制账户当前显示的对应格式地址，在保留旧配置的前提下新建一个配置进行验证；账户状态正常而仍被拒绝，就向实际提供方提交脱敏错误。继续切节点不能修复认证参数本身。

429：暂停频繁刷新

429 表示请求过多；响应可能提供 Retry-After 等等待提示。先停止手动连续更新，并查看软件是否同时启用了过于频繁的自动更新，按实际服务说明调整。若有明确等待时间，等待后再做一次验证，不用多设备同时刷新来试探限制。

超时、找不到主机：区分基础网络与该地址访问

先在当前网络打开一个普通、无需代理的小网页，确认不是 Wi-Fi 登录门户或整条网络未连接。基础网络也失败时先处理接入，不继续修改订阅内容。

基础网络正常时，保留当前错误，在有权使用的另一个网络做一次同地址对照。只改变网络，不同时更改客户端、格式和地址。对照成功只能说明访问路径可能有关，不能据此断言某个运营商封锁；两边都失败也不足以判断服务已永久停止。交给实际支持方核查地址和服务端日志。

如果软件明确支持选择订阅更新的连接方式，先查看该版本文档并记录原值，再考虑一次短时对照；测试后恢复。不要让失效配置成为更新它自身的唯一依赖，也不要关闭证书校验来绕过报错。遇到证书警告应停止访问，核对设备时间及提供方公告。

下载成功，为什么仍然无法解析

“收到响应”和“收到有效配置”是两件事。登录页、验证页或服务端错误文本也可能被下载。客户端若提示 HTML、未知字段或格式不合法，记录错误类别和涉及的字段名，不公开整个响应。

  1. 对照提供方说明，确认选用的订阅格式与当前客户端、内核兼容。不要把另一种客户端专用格式当成通用格式。
  2. 查看软件自身的更新说明，确认该字段是否需要不同内核版本。没有兼容依据时，先保留现状，不为了消除报错随意删字段。
  3. 如存在自己的覆盖规则或脚本，用软件支持的方式保留原配置，在独立测试配置中先验证未经额外加工的输入。原始配置可用、加工后失败时，再检查自己的改动；两者都失败则继续查格式或提供方响应。
  4. 不把私人订阅交给陌生在线转换站。确实需要格式转换时，先确认提供方是否有兼容入口，或使用你能够核对来源与数据处理方式的工具。

成功表现是配置通过客户端校验并可被选为当前配置，而不是只出现“下载完成”。如果只恢复了下载但仍报解析错误，故障还没有解决。

导入完成却看不到节点

先查看刚导入配置的名称与更新时间，再确认当前启用项是不是这份配置。多个名称相近的配置容易让人以为更新无效。只切换当前启用项进行检查，不删除其他配置。

接着核对界面是否只展示策略组、是否存在搜索筛选，以及提供方是否说明另需加载外部节点源。看到策略组名称不等于看到其中所有节点；不同软件显示方式不同，按对应教程展开检查。外部资源若单独更新失败，应记录该阶段错误，不能用主配置更新成功替代它。

若清除自己设置的界面筛选后仍为空，回到账户确认可用套餐和服务范围，再向提供方询问该格式的有效配置是否包含节点。不要自行编写陌生节点地址来填满列表。对于来源不明或内容异常的配置，不强行启用其中的脚本和路由设置。

地址更换、迁移与泄露后的处理

更换订阅地址前，列出自己使用过该地址的设备与配置。先在一台设备新建配置完成更新和连接验证，再逐台替换，避免所有设备同时失去已知可用配置。确认新配置能用以后，再通过软件正常操作移除已废弃副本；手工规则是否迁移要单独核对，不能假设自动继承。

若地址曾被公开，删除聊天内容并不能确保凭据失效。通过实际提供方提供的撤销或重置功能处理，并了解这会使哪些现有设备需要重新导入。不要把新地址再次发到公开评论中证明“已经换了”。无法找到重置功能时，联系实际账户支持，保留旧地址已泄露的时间范围即可，不需要把它再发给无关人员。

怎样确认已修复及向谁反馈

一次完整验证应包括：更新成功、配置校验通过、选中该配置后能看到相应节点或策略，再完成一个正常的小请求。若新配置不能工作，按软件正常流程切回仍有效的旧配置；旧地址已撤销时不要反复尝试使其重新生效。

反馈时描述“原来可更新，某日开始请求返回403”或“下载成功但解析字段失败”，并附系统、客户端及内核版本、格式类型、发生时间与时区、一次网络对照结果。订阅地址、响应全文、密码和二维码都应遮盖。

账户拒绝、地址生成与服务端响应问题优先联系实际提供方；仅某版本客户端无法解析而其他兼容版本正常时，可向客户端项目提交最小化且不含私人节点的复现信息。不要把公开 Issue 当成传送个人配置的渠道。
